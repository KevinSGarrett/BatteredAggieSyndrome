# National frozen shallow-tree comparison 2016-2023 (BAT-736, Cycle #65 TP65-A01)

Bounded research contribution to BAT-423 (model baselines and comparisons): two frozen shallow tree probability models
compared with the five unchanged C56 controls on the same games. It does not complete BAT-423 (other tree families,
market baselines and bounded searches stay open), BAT-425, or any personnel, weather, coaching, matchup, film or engine
obligation.

## Authority and limits

Every record and answer is RETROSPECTIVE_RESEARCH, UNTRUSTED_SHADOW, PIT_NOT_ADMITTED and NOT_A_FORECAST with predictive
skill and calibration NOT_ESTABLISHED; no champion is selected and no causal claim follows. The 2023 games are an already
exposed descriptive comparison (ALREADY_EXPOSED_DESCRIPTIVE_COMPARISON_NOT_BLIND), never a blind or protected test: the
C56 parent's 2016-2023 outcomes, scores and summaries were published before the two definitions were frozen, and the
worker read the parent summary while qualifying the parent before any fit. No 2024, 2025 or 2026 outcome is selected,
read for modeling or scored (the parent holds only 2016-2023 targets). Both trees losing to the controls is a valid
completed result; an integrity or runtime failure stays a failure.

* Exactly two model definitions exist, frozen in the committed contract before any real fit: `HIST_GB_DEPTH2_V1` and
  `HIST_GB_DEPTH3_V1` (scikit-learn 1.9.0 `HistGradientBoostingClassifier`, every one of its 21 constructor options
  explicit: log loss, learning rate 0.05, 100 iterations, at most 8 leaves, 20 samples per leaf, L2 1.0, 255 bins, no
  early stopping or validation split, seed 0, no class weight; maximum depth 2 or 3). Repeated executions of the same
  definition prove determinism or reproduce it independently; they are counted and must export identical bytes. There is
  no search, tuning, calibration, refit or winner selection.
* Training uses only the 5,087 decisive 2016-2022 games: two oriented rows each (A, then B with the negated design and
  the complementary label), weight 1/2 per row. The 788 games of 2023 are never in a fit.
* The ten columns are the unchanged C56 difference columns (games, win rate, points for, points against and margin means
  and their five missing-indicator differences), each exact rational converted once to binary64. Known redundant
  columns are retained. No source, site, personnel, weather or market feature is added.
* The backend is build-only (the pinned offline runtime). Readers and the installed query use the standard library and
  never import a modeling package.

## Inference and scoring

* Traversal: start at the binary64 baseline; in each of the 100 stages go left when x[feature] <= threshold, otherwise
  right (a NaN, which no real feature is, follows missing_go_to_left); add the leaf value (already scaled by the learning
  rate) and check the margin is finite after every addition; stable sigmoid. A nonfinite margin is TREE_ESTIMATE_MISMATCH
  reason TREE_MARGIN_NONFINITE.
* Served pair: p_A = (q_A + (1 - q_B)) / 2 in binary64 from the stored raw witnesses, quantized half-even to 12 places in
  a fixed decimal context (precision 50, half-even, traps InvalidOperation, DivisionByZero and Overflow, no flags); B is
  the exact complement. The ambient decimal context is never read or changed.
* Scores: Brier is the exact rational of the served decimal; log loss clips only its logarithm argument to
  [1e-15, 1 - 1e-15]. Summaries sum stored per-game values in canonical game order (math.fsum for log loss).
* Portability: a reader recomputes the tree margins exactly, the raw probabilities and log losses within absolute 1e-12,
  and checks log-loss aggregates from the stored per-game values within the same tolerance. Brier, counts, served
  probabilities, cohorts and calibration stay exact. Tolerance never permits altering a stored value or skipping the
  profile.

## Reader and query (explicit mode only)

`bas-retrospective-baseline-query --boosting-comparison <database> --grain {tree-feature,tree-parameter,tree-estimate,
tree-score,tree-summary} [--season] [--team] [--contest] [--model] [--partition] [--slice] [--limit] [--offset] [--all]
[--manifest] [--expect-identity]` (also `python -m aggie_analytics.retrospective_baseline.query` and
`aggie_analytics.retrospective_baseline.boosting_comparison.query`). The legacy `--help` gains exactly one appended
paragraph; every other legacy invocation is unchanged.

Before any file is read, in this order: another mode's option (TREE_MODE_CONFLICT), `--require-pit`
(TREE_PIT_NOT_ADMITTED), any provided `--as-of` (AS_OF_STATE_NOT_SUPPORTED), grain, season, team, contest, model,
partition, slice, applicability (FILTER_NOT_APPLICABLE), `--all` with an explicit limit or offset (PAGING_CONFLICT),
limit, offset and the expected identity (STALE_TREE_IDENTITY). Raw Unicode Cc controls and lone surrogates are refused
before U+0020-only trimming; typed integers are bounded before any text conversion; diagnostics never echo oversized
integers, nested objects or surrogates. Then the literal local spelling of the database and the manifest, the layout on
the genuine on-disk names (8.3, case, long, relative and junction spellings of the genuine release serve identical
bytes), the manifest identity and database hash, the parent BLOB (type, bytes, SHA-256 before parse), the parent's schema,
blocks and witnesses, and every record, collection, tree, traversal, estimate, score, summary and identity, ending with the
pinned profile (STALE_TREE_IDENTITY). `--expect-identity` only adds the caller's own identity assertion (a mismatch is
STALE_TREE_IDENTITY first); it never replaces the pinned profile, which binds every release whether or not the option is
given (MF65A01-01), so a self-rehashed copy within the numeric tolerance is refused even under its own identity.

Selection: applicable filters intersect canonical game keys first; a team matches either participant (`org:<digits>`,
bare digits, or the parent source team name of that season, casefolded by the committed parent rule; a name matching two
keys in one season is TEAM_AMBIGUOUS); an unknown or disjoint selection returns zero rows. The summary is re-derived over
exactly the selected games (default slice NATIONAL). Paging: default 50/0; limit 0 is count-only.
