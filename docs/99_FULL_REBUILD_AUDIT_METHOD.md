# Wave 18 Full-Rebuild Audit Method

> **Wave 18 full-rebuild status:** reference implementation + governance contract. No protected model result or production promotion is claimed.

## Why another rebuild was necessary

The earlier W18 packs passed structural hash/count checks but were too shallow relative to the requested program depth. This full rebuild treats those artifacts as rejected drafts and audits *substantive subsystem coverage* in addition to cumulative integrity.

## Audit dimensions

The audit checks: exact W17 preservation; master Wave-18 item coverage; W18 task outputs; documentation depth; executable reference modules; negative-governance tests; tournament/HPO/replay/store/worktree functionality; acceptance/REQ/ADR/RISK traceability; package root identity; deterministic packaging; hydration binding; and W18→W19 readiness.

## Size is not the acceptance criterion

A larger ZIP is not automatically better. The rebuild intentionally adds more code/spec/evidence because missing subsystem depth required it, not to hit an arbitrary megabyte target. Final acceptance is based on named requirements and executable gates.

## Rejected artifacts

The earlier W18 draft/corrected hashes are recorded in the correction ledger and must never be accepted as W19 parents after the full-rebuild pair is issued.
